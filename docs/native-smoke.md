# Native macOS smoke checks

The UI preview mocks IPC. Use this separate native bundle to check real WKWebView events, native content-rule enforcement, and PTY lifetime without replacing the installed Flux app.

## Build and launch

With the project's dependencies already installed:

```sh
node scripts/native-smoke-build.mjs
node scripts/native-smoke-server.mjs
```

Open `target/debug/bundle/macos/Flux Smoke.app`, then navigate its address bar to `http://127.0.0.1:8851/`. The fixture server binds only to loopback. Stop it with Ctrl+C when finished and quit Flux Smoke normally.

The build uses `native-smoke` and the `dev.flux.smoke` identifier. Its session, preferences, and web data belong to that separate app. Legacy pre-Tauri log/clear-marker paths use a temporary directory, OS credential access uses an in-memory keyring, service autostart and automatic filter refresh are disabled, and the test editor uses a separate socket range with `nvim --clean`. This harness checks browsing and PTYs, not credential persistence or the user's editor plugins. It is a developer test build; do not install it as your everyday browser. The normal build does not enable these overrides. The runtime rejects a smoke build with the production identifier or without the matching frontend build flag.

## Repeatable checks

1. **Title and navigation.** Page A should show the same title in the tab strip. Click **Change title after load**, then **Go to page B**, Back, and Forward. Compare the rendered page, address, and tab title each time. The delayed title must update without navigating.
2. **Native blocking.** In a browser without Flux's synthetic rule, run **Run blocking probe**: both resources must load and reach the server. Then run it in Flux Smoke. The allowed script must reach the server; the blocked script must fail without appearing as a new request in the server log. Both endpoints return successful JavaScript when reached, so a missing blocked request plus the working control distinguishes filtering from an absent resource. The harness adds one synthetic ABP rule through Flux's production filter translator and native attachment code. This does not measure coverage of public filter lists.
3. **Protection UI.** Open Shields on the fixture page. Check **Native blocking rules attached**, the page's blocked count (1 after a probe: the chip in the address field and the popover's domain list both show it), and disabled HTTPS-only, tracking and Lean controls. Do not interpret rule attachment alone as proof of blocking; use step 2. `http://127.0.0.1:8851/?auto` runs the probe on load, and `RUST_LOG=flux::netfilter=debug` logs each block WebKit reports ("WebKit blocked").
   - **Per-site switch.** Turn Shields off for 127.0.0.1 in the popover: the page reloads and the probe's blocked script reaches the server. Turn it back on and it's blocked again.
   - **Hide an element.** Choose **Hide an element on this page…**, click the yellow promo box: it disappears. Reload: it stays hidden (the page logs `promo display: none` to the server). **Show 1 hidden element on this site again** brings it back after the reload.
4. **Tab sleep.** Open `http://127.0.0.1:8851/?beat` in two tabs, scroll one down and switch to the other. The page sends a heartbeat to the server every half second, with its scroll position. In Settings → Memory, set **Unload after** to 5 min and wait: at 5 minutes the background page is suspended and its heartbeats stop (`RUST_LOG=flux::sleep=info` logs the steps). Unload it with ⌘K → **Sleep background tabs**: its row shows the moon. Switch back: the card shows the page as you left it, scrolled, until WebKit reports its first paint (`waking an unloaded tab … restored=true`), and the heartbeats resume at the same scroll position.
5. **Agent task steps.** Open `http://127.0.0.1:8851/agent` and ask the agent `/task search for blue mug, show the delivery details and send the message`. Typing into Search and **More details** run on their own; each feed line names the step's kind (Read, Draft, Commit) and what the page showed (`✓ the field holds it`), or says `applied, unverified` when a fresh look didn't show it (**Does nothing** is there for that). **Send message** asks once, with a preview (`Click “Send message” on 127.0.0.1 (sends the form)`), and the server logs `Message sent: ?msg=hello` once. Steps Flux never takes are refused before anything runs: typing into **Card number**, following **Pay from your bank**, and clicking **Place order** (yours to do, #104). The finish says `✓` only when every step showed on the page. `http://127.0.0.1:8851/agent-signin` hands off (**I'm done**, **Skip this page**, **Keep waiting**, **Stop**). That page hides its password field from its own scripts, so a hand-off there also shows Flux looks from its own JavaScript world. `RUST_LOG=flux::agent=info` logs each planned step.
6. **Form help.** Turn on Settings → Form help, then open `http://127.0.0.1:8851/form` (the setting applies to pages loaded after it). Click into **What's your favourite colour?**: the answer shows greyed out with a Tab chip, and Tab puts it in. ⌃Space asks again; pressed while a suggestion shows, it asks for a different one. Click into the empty **Why do you want to volunteer with us?** box: the chip says **Copied**, and ⌘V pastes the answer. The rich-text box under it behaves the same. Email, Card number and the sign-in form's Login get nothing. `FLUX_AGENT_BACKEND=mock` answers without a model ("Mock answer"). A textarea the page focuses itself can't be copied to (WebKit allows a clipboard write only inside a click or keypress), so its answer shows as ghost text instead.
7. **Cited answers and restyle.** Open `http://127.0.0.1:8851/article` and, in the agent's **This page** scope, ask "what do positional encodings add, and how do learned ones compare?". The answer carries numbered marks; clicking one scrolls the page to its passage, highlights it and badges it with the number (the page's own "[2]" footnotes don't count as citations). A comparison comes with a table whose Source column shows each claim as Supported, Inferred, Unverified or Contradicted; Copy CSV copies it, and the headers sort it. **Make tasks** proposes up to six tasks to tick and add; **Save as note** writes the answer and its quoted sources to the vault's Flux Notes folder. `/restyle larger text, hide the sidebar` previews on the page at once (the sidebar goes, the text grows) and says how many rules matched nothing; **Apply** saves it as a Boost for 127.0.0.1, **Discard** puts the page back. `FLUX_AGENT_BACKEND=mock` answers both without a model.
8. **Time and focus.** Open `flux://time`, add `127.0.0.1` to the sites to close and **Start focus**. Then type `http://127.0.0.1:8851/` in the address bar: the tab shows "127.0.0.1 is closed while you focus" with the time left, and the server logs no request. **Allow 5 minutes** loads the page; End focus would too. A link or script that sends a page on another site to 127.0.0.1 is stopped the same way, and the cover adds **Stay on this page**. The new tab's strip shows Blocked today, Focused against the goal (2h until you change it), and Due today. Time counts only while Flux is in front: after a few minutes on the fixture page, `flux://time` lists 127.0.0.1 under Today, and the minutes stop while another app is in front. Private tabs aren't counted, nor a site while its cover is up.
9. **Keys and the menu bar.** The menu bar has File, Edit, View, History, Bookmarks, Go and Window, each command with its key (⌘T New Tab, ⇧⌘] Next Tab). Show Tabs (⌥1) shows none: a menu key without ⌘ would be checked before a text field gets it. A command picked from a menu runs as its key does. ⌘T opens one tab, from a page and from the chrome alike: the key the page or chrome handles never reaches the menu. In Settings → Keyboard, click Tasks' shortcut and press ⇧⌘K: "⇧⌘K is used by Launcher". **Use here** moves it, and at once Go → Tasks shows ⇧⌘K, ⇧⌘K on the fixture page opens Tasks, and ⇧⌘K no longer opens the launcher. Pressing ⌘Q while recording says the system owns it; Close tab's shortcut can't be clicked. Esc cancels, ⌫ takes a shortcut off, ↺ puts one back, and the choice is kept after a restart. In the fixture's text field ⌥← moves a word and ⌥1 types ¡; outside it they go back and show the tabs.
10. **Welcome and import.** ⌘K → Welcome to Flux opens the six steps; each has Skip, and Close setup or Esc leaves. Step 2 lists Chrome, Arc, Safari, Firefox, Brave and Zen (Edge and Chromium when they're here): a detected one with its profile and counts, one macOS keeps from Flux as locked with **Open Full Disk Access** and **Check again**, a missing one as not found. **Import and continue** brings the checked ones' bookmarks (each browser's bar to Flux's bar, the rest under the browser's name), the last 180 days of history, and Arc's pinned sites and Favorites (under Arc/<space>), and says how many; the other browser can stay open, and importing again adds only what's new. Step 3's tiles come from that history and land under the new tab's clock. A fresh profile (Flux Smoke with its data folder emptied) opens the welcome by itself, once; one with history never does.
11. **Page and PTY retention.** Type a marker in the fixture input. In a terminal, set a shell variable and print it with the process ID. Apply Browse to hide panels and reopen the terminal. Print the variable and PID again; both must match. Repeat with multiple terminal panes. Type unsaved text into the clean editor, hide it with Browse, and show it again. The text must remain. Check the page input while resizing or toggling panels.
12. **Keyboard and native accessibility.** Open the command palette using Command+K from a page. The native page and background chrome must leave the accessibility tree while the palette is open. Tab and Shift+Tab must stay in the palette; Escape must dismiss it and return focus. In Settings → Terminal, enable **Terminal screen reader support**. Existing editor content and newly printed terminal output must become accessible without restarting their PTYs. The covered page placeholder must not announce perpetual loading. Check named switches and disabled states in Settings and Shields.
13. **VoiceOver.** With VoiceOver working on the test machine, repeat the palette and Settings flows and read terminal output rows. Accessibility-tree checks alone do not verify spoken output, announcement timing, or the quality of full-screen TUI navigation.

## Recorded run — 12 September 2026

Passed on the rebuilt macOS native bundle:

- Delayed title updates and link/Back/Forward title–URL alignment.
- Successful control resources in the in-app browser; only the allowed request reached the local server from Flux Smoke.
- Native attachment status, unavailable counters, and disabled WebKit controls.
- Same shell PID and in-memory variable after hiding/reopening both a single terminal and the second pane of a split; unsaved page input retained across panel changes.
- Unsaved clean-Neovim buffer retained across Browse and editor reopening.
- Command palette Tab containment, Escape dismissal, native-page restoration, and background accessibility isolation.
- Enabling screen-reader support exposed an existing unsaved editor buffer and new terminal output in macOS accessibility; the underlying loading placeholder was absent.

VoiceOver launch timed out. A subsequent app inventory showed VoiceOver was not running. Spoken-output validation remains pending. Native window resizing and full-screen TUI announcement quality were not verified in this run.

The macOS/Windows CI jobs compile and test platform-specific Rust paths. They do not automate these GUI checks and were not executed remotely during this local run.
